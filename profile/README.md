## What we build

8x8 is an evolving product ecosystem spanning AI experiences, creator tools, identity, public verification, digital assets, research and intelligent workflows.

Public repositories and hosted experiences are intentionally scoped to the parts that users, customers, integrators and contributors need. The proprietary implementation behind 8x8 products is private unless a component is explicitly released as public/open source.

### Public product surfaces

| Product | What it is | Current public scope |
|---|---|---|
| **8x8 User Edition** | Public-facing 8x8 experience, product information and approved user workflows | Beta / evidence-gated |
| **Public Fabric** | Hosted public experience and product demonstration | Public carrier; scope varies by release |
| **8x8 Protocol** | Intentionally public schemas, verification formats and interoperability contracts | Public reference material under review |
| **Public Program** | Public roadmap, competitions, contribution opportunities and evidence-backed progress | Active public program |

Additional 8x8 products and services may be introduced through hosted applications, APIs, clients, packages or documented integrations without publishing their private implementation.

A product name or public capability does not imply that its private backend, internal algorithms, operational tooling or privileged controls are published.

## Public/private boundary

Public users receive **products and capabilities**, not a downloadable copy of the private 8x8 system.

The public boundary is designed around this pattern:

```text
user / customer / integrator
          ↓
public 8x8 product, client, API or documented contract
          ↓
authenticated and policy-controlled service boundary
          ↓
private implementation
```

Public repositories do not intentionally expose owner credentials, signing material, raw provider secrets, private messages/memory, internal runtime topology, private deployment/recovery procedures, proprietary orchestration logic or source sufficient to reproduce the private One-Fabric system.

## Evidence before claims

8x8 public releases distinguish design, implementation, testing, deployment and adoption rather than treating them as the same state. Public financial, benchmark, competition and deployment claims require evidence appropriate to the claim.

Screenshots, concepts and source files are not automatically proof that a production capability is live.

## Security and privacy

- Never commit credentials, keys, seed phrases or private account data to public repositories.
- Private-system implementation stays private unless an explicit publication decision says otherwise.
- Public examples use approved fixtures or public-safe data.
- A public API/schema may be open while the service implementation remains private.
- Historical public disclosure is treated separately from current repository cleanup; a real exposed secret must be rotated, not merely deleted.

See [`SECURITY.md`](../SECURITY.md) and [`PUBLIC_REPOSITORY_STANDARD.md`](../PUBLIC_REPOSITORY_STANDARD.md).

## Public-source policy

8x8 does not use “public repository” as a synonym for “all internal source is open.” Each repository or component has its own publication scope and license. If implementation source is intentionally open, that decision is stated explicitly in that repository.
