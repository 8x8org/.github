# 8x8 OS 0.0.1 Beta — Master Presentation, Definition, System Map, Teaching Guide, and Audit Summary

Date: 2026-08-07
Truth class: evidence-backed synthesis of the connected GitHub estate plus explicitly labeled wider-system context. This report does not claim whole-estate completion, production stability, or exhaustive local-runtime verification.

## Executive introduction

8x8 OS is an evidence-governed operating system for coordinating humans, AI agents, software services, devices, repositories, models, connectors, memories, missions, public products, and experimental futures under explicit identity, authority, context, evidence, reality, and rollback rules.

The system is broader than GitHub. GitHub is the public and collaborative projection. The wider estate also includes Android/Termux, Ubuntu PRoot, Hermes coordination, local services, agent registries, memory stores, automation lanes, models, connectors, Studio/media tooling, blockchain/testnet research, and deployment infrastructure.

Canonical whole-system product maturity: **0.0.1 Beta**.

Historical service generations, MSG IDs, protocol revisions, branch names, and implementation numbers remain implementation metadata and do not imply product maturity.

## The central idea

8x8 should make every meaningful action answer:

1. Who or what acted?
2. Under whose authority?
3. Using which version of shared truth?
4. In which reality and privacy boundary?
5. Through which tools, models, connectors, nodes, and repositories?
6. What evidence proves the result?
7. How can the action be revoked, corrected, superseded, or rolled back?

This is the intellectual center of the system: **legible autonomy** rather than unrestricted autonomy.

## Three Realities

The Past, Present, and Future are native system states.

### PRIVATE_PAST

Private operational history, memory, evidence, superseded implementations, recovery state, runtime truth, private repositories, archived decisions, and historical receipts.

### PUBLIC_PRESENT

The current privacy-safe, evidence-backed public projection. Only reviewed, verifiable, non-sensitive capabilities and claims belong here.

### FUTURE_LAB

Research, external capability candidates, experiments, simulations, new models, new worlds, new bodies, prototype connectors, testnet economics, architecture proposals, and unpromoted work.

### PROTECTED_BETA

A transition state between Future Lab and Public Present. It is not a fourth reality.

Promotion requires evidence, tests, provenance, privacy/security review, rollback, and owner approval.

## Core technical primitives

### Global Context Snapshot

A signed/shared context state intended to keep productive agents aligned to the same current system truth.

### Proof-Carrying Mission

A mission should bind owner intent, context digest, agent/body/session identity, authority lease, capability set, execution events, acceptance tests, artifact hashes, cleanup, rollback, reality classification, and final receipt.

### Proof Graph

Owner Intent → Policy → Context → Lease → Mission → Agent/Body → Tool/Model/Connector Calls → Artifacts → Tests → Receipt → Public Claim.

### Contradiction Ledger

Conflicting system claims should be preserved, compared, resolved, and superseded explicitly instead of silently overwritten.

### Capability Constitution

Every agent, model, tool, connector, service, or plugin should declare allowed powers, denied powers, data classes, resource limits, approvals, tests, cleanup, rollback, and public-projection rules.

### Public Projection Compiler

Public READMEs, dashboards, release notes, badges, and claims should eventually be generated from approved Present evidence and fail closed on stale, private, or unsupported information.

## Teaching guide: how to think about 8x8

### Lesson 1 — GitHub is not the whole system

GitHub stores code, documentation, evidence, issues, PRs, and public collaboration. The live runtime exists elsewhere. Never equate a commit with a deployed service.

### Lesson 2 — A claim is not a deployment

Use the evidence ladder. A README can establish a CLAIMED state. Code can establish IMPLEMENTED. Tests can establish TESTED. Runtime evidence is needed for RUNNING/DEPLOYED. Public release requires separate proof.

### Lesson 3 — Past, Present, Future are executable boundaries

Past preserves private and historical truth. Present is public, current, verified projection. Future is research and experimentation. Promotion between them must be explicit and reversible.

### Lesson 4 — Autonomy is bounded

Agents should act through leases, explicit capabilities, exact targets, acceptance tests, cleanup, and receipts. Autonomy without authority boundaries is not a feature.

### Lesson 5 — Evidence is the connective tissue

Every important system state should eventually resolve to evidence: a hash, receipt, CI run, runtime observation, signed manifest, test result, or owner-approved record.
