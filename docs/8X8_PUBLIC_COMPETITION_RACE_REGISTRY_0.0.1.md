Canonical root: `fabric://8x8/core`

This registry makes competition participation transparent without allowing hackathons, grants, races, or prize programs to override the 8x8 architecture, evidence law, security boundary, rollback discipline, or owner authority.

## Status vocabulary

- `SUBMITTED_FROZEN_AWAITING_RESULT` — an external submission exists and organizer rules require it to remain unchanged pending results.
- `ACTIVE_BUILD_NOT_SUBMITTED` — active work exists, but no final external submission receipt exists.
- `WATCHLIST_NOT_ENTERED` — a verified public competition is relevant to 8x8, but registration/submission is not claimed.
- `UI_ATTACHMENT_PENDING` — the public issue exists, but attachment to GitHub Projects v2 has not yet been independently observed.

## Fair-race policy

1. Never claim `SUBMITTED`, `FINALIST`, `WINNER`, `DEPLOYED`, user counts, revenue, benchmarks, uptime, production calls, or judge access without receipts.
2. Publish public-safe status, official rules, deadlines, provenance, blockers and results.
3. Keep credentials, PII, private topology, private agent coordination, privileged runtime evidence and security-sensitive details private.
4. Preserve frozen submissions exactly when organizer rules require it.
5. Competition-specific constraints are adapters/projections, not One-Fabric constitutional law.
6. Useful competition work should converge back into durable 8x8 capabilities.
7. Missing a deadline is preferable to weakening 8x8 correctness, security or evidence integrity.
8. `fabric://8x8/core` remains canonical.
