**Public checkpoint: 2026-08-22**

## What 8x8 is

©️8x8 by FlashTM8 ⚡️🌎🤖 is an evolving One-Fabric product ecosystem combining identity, AI/agents, Studio/creator workflows, device participation, social/connectors, wallet/chain research, market intelligence, proof/evidence, missions and public user experiences under one account and permission model.

The public experience is a projection of the product. Private OWNER_ROOT controls, credentials, signing material, private memory/messages and proprietary orchestration are not published.

## Which interface is current?

The old `horbolsi/8x8-OS-Ecosystem` React/Express repository and the `horbolsi/8x8-os-a-z` ASCII console remain useful public demos and historical donors. **They are not, by themselves, the canonical description of the current interface.**

Current public-safe interface direction is a responsive spatial cockpit organized around:

`HOME / WORLD / AGENTS / STUDIO / MARKET / CHAIN / PROOF`

with account/identity, Studio, agents/presence, wallet/chain, connectors, evidence/proof and progressively released user workflows in one client.

The current protected user release train also includes an opt-in **Nearby / Missions** surface for future verified partners such as shops, hotels, services, NGOs and institutions. Its model supports evidence-backed missions (for example receipt/document/location/selfie evidence), points and reward entitlements while keeping actual token distribution or outgoing reward payment separately gated.

## Current partner / mission economy truth

The production data plane now contains the partner/mission/reward schema required for verified nearby missions. This is **infrastructure presence**, not evidence of active commercial partnerships.

Current public-truth boundary:

- partner organizations, partner memberships and watch-only partner wallet projections are supported by the data model;
- mission types include shop purchase, hotel stay/check-in, visits and document-verification workflows;
- mission evidence is represented by hashes/opaque private-object handles rather than raw media in ordinary mission tables;
- task completion can award points and create reward **entitlements**;
- a verified claim does **not** itself execute a token airdrop or move money;
- no organization should be described as an active 8x8 partner without current partnership evidence.

## Money / token truth

As of this checkpoint, do **not** infer live revenue, token distribution or settlement from product/source presence.

- live subscription/payment settlement is not yet proven;
- verified crypto treasury-receive endpoints required for live collection are not yet proven;
- wallet/server signing remains disabled for the protected public-user path;
- minting, token airdrops, funded liquidity and live trading are not activated by this public checkpoint;
- planned token identities or reward entitlements are not the same thing as issued/on-chain tokens.

Accordingly, statements such as “the token is live,” “airdrops are active,” “Telegram is fully released,” or “22 modules are the complete current system” require newer direct evidence before they can be made.

## Revenue model vs. current revenue

Potential revenue/product lanes include subscriptions, creator/Studio services, partner programs, marketplace/service fees and other separately approved value-bearing products. These are **business/product directions**, not guaranteed revenue.

The evidence standard is simple: a configured provider, price, invoice, checkout button or source file does not become revenue until a real accepted/settled transaction can be reconciled from the provider and application state.
