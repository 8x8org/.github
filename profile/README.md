## What 8x8 is

8x8 is a continuous, multi-year system rather than a collection of isolated applications or chats. The public organization is one privacy-safe projection of the wider One Fabric; it is not the entire private runtime estate.

8x8 is designed around a verifiable chain:

`Owner intent → policy → shared context → capability/authority → lease → mission → agent/body identity → execution → tests → receipt → public claim`

The goal is not merely autonomous output. The goal is **legible, bounded, reversible, evidence-backed autonomy** across human and AI work.

## One interface, multiple authority projections

The target product model is `ONE_INTERFACE_MULTI_AUTHORITY_PROJECTION`.

The same responsive 8x8 application/component system can serve an owner, an ordinary user, an agent or a service subject, while `8x8 Account + 8x8 ID + policy` determines which data, controls and external capabilities are visible and executable.

A shared interface is never a shared secret boundary. Private owner controls, raw credentials, signing authority and protected system topology remain inaccessible to ordinary users unless an explicit capability and evidence gate says otherwise.

## Five nested fabrics

The wider system is currently described as five cooperating fabrics:

1. **Sovereign Fabric** — owner identity, 8x8 ID, permissions, devices, leases, emergency control, private state and rollback.
2. **Intelligence Fabric** — FlashTM8 Agent intent/orchestration, Hermes, agents, councils, models, Universal Router, research, teaching and evaluation.
3. **Continuity Fabric** — memory, messages, context snapshots, ledgers, evidence indexes, recovery and historical provenance.
4. **Execution Fabric** — Termux, Ubuntu PRoot, services, bots, missions, schedulers, GitHub Actions, cloud runtimes and deployments.
5. **Experience Fabric** — First Blink, Live Reality Graph, World, Art Board 360, Command Deck, Council Wall, Memory Graph, Operator HUD, Studio, voice, mobile and spatial interfaces.

Capability families include agent identity and coordination, model/provider routing, memory, automation, evidence, security, hardware/device mesh, connectors/Vault, Studio/media, trading intelligence, blockchain/testnet/8x8Scan/wallet research, public spatial UX, release operations, community, Academy, venture and governance systems.

See the [current Fabric System Map](../docs/8X8_OS_0.0.1_FABRIC_SYSTEM_MAP.md).

## Benchmark and rank law

8x8 aims to improve until it can lead relevant benchmarks, but **rank is an evidence result, not a permanent identity**.

`TOP_1`, `BEST`, `100/100` and numeric scores require a named benchmark/version, frozen denominator, exact source/runtime/model/provider/configuration, comparable reference results, timestamp/environment, raw reproducible receipt and an invalidation/freshness rule. External ranks additionally require an authoritative external result.

Historical self-scorecards are preserved as `PAST_PRESERVED`; they are not current whole-system ratings. See [Benchmark & Rank Program #24](https://github.com/8x8org/.github/issues/24).

## Community, project sharing and reputation

The planned community layer follows explicit user consent:

`8x8 Account → 8x8 ID → connected identity → selected public project/repository → global feed/chat → follows/channels/missions → verified task receipts → points → leaderboard/reputation`

Connecting GitHub or another provider does **not** make every repository/account object public. Users choose what to share; private repositories and raw provider credentials remain private by default.

Community points/reputation are receipt-backed and anti-abuse. They do not silently imply money, ownership, employment or system authority. Referral rewards remain non-financial reputation/points until a separately reviewed economic program is activated. See [Community Network #28](https://github.com/8x8org/.github/issues/28).

## Evidence before claims

The public evidence ladder is:

`CLAIMED → DESIGNED → IMPLEMENTED → TESTED → VERIFIED → RUNNING → PRODUCTIVE → DEPLOYED → PUBLICLY_RELEASED → ADOPTED`

Where authority is involved, also distinguish:

`CATALOGED → REGISTERED → AUTHENTICATED → SCOPES_VERIFIED → GRANTED → LEASED → EXECUTED → RECEIPTED`.

A README, screenshot, issue, commit, process or design does not by itself prove deployment, productivity, authority or stability.

`100/100` is valid only for a declared denominator/scope at an exact timestamp. A continuously evolving Fabric can lose evidence freshness after a change and regain 100/100 only when the affected scope is re-verified.

## Public/private boundary

This organization does not publish or grant owner credentials, signing keys/private wallets, raw OAuth/API secrets, private repositories/messages/memory/prompts/telemetry, privileged device/shell/service/database access, unrestricted autonomous financial authority or the sovereign private control plane.

Public clients are policy-filtered consumers of approved capabilities. They are not downloadable copies of the owner system.

8x8 development is owner-sovereign, permission-first, rollback-preserving and evidence-gated. Public collaboration grants no private owner authority, financial authority or private-control access. See [`GOVERNANCE.md`](../GOVERNANCE.md).
