## Critical contradictions and gaps

### Version drift

Some open PRs and historical artifacts still use `0.1`, `0.1.x`, or V1 naming in user-facing contexts. Internal generation identifiers may remain, but product-facing maturity must converge on `0.0.1 Beta`.

### Project drift

The public-program Project is empty despite many active issues and PRs. There is no automatic item ingestion, no visible roadmap, no owner field, no reality field, no evidence field, and no public contributor queue.

### Discussion drift

The repository has Discussions enabled, but community operations are effectively inactive. The default welcome message is not a community program.

### Organization metadata drift

The organization description remains narrower and older than the profile README. Repository descriptions, topics, websites, social previews, and pinned-repository choices require a full metadata audit.

### Repository-role drift

The 16 repositories still need one canonical role, maturity state, owner, reality, evidence state, security boundary, and supersession relationship. Multiple repositories appear to overlap in backup, unified, hub, private, historical, and memory responsibilities.

### Public/private presentation imbalance

The public estate emphasizes boundaries and disclaimers more strongly than demonstrations, screenshots, examples, contributor tasks, and verified achievements. The caution is correct, but the experience currently leads with limitation rather than value.

### Growth-system absence

- roadmap voting;
- newcomer issues;
- contributor recognition;
- demo publishing;
- social distribution;
