# 8x8 Security Policy

## Report privately

Do not disclose suspected vulnerabilities, credentials, private URLs, personal data, wallet information or exploit details in a public issue.

Use the affected repository's **Security** tab and select **Report a vulnerability** when GitHub private vulnerability reporting is available.

When that option is unavailable, email `xorgbytm8@gmail.com` with the subject prefix `[8x8 SECURITY]`. Include only the minimum information needed to establish contact in the first message. Do not attach secrets, private keys, seed phrases or real user data.

## Include

- affected repository and exact commit or release;
- affected component and environment;
- reproducible steps using synthetic data;
- expected and observed behavior;
- likely impact;
- suggested mitigation, when known;
- a safe contact method.

## Response expectations

Receipt will be acknowledged when the report is reviewed. Severity, remediation and disclosure timing depend on reproducibility, impact and maintainer availability. No bounty, payment or publication deadline is promised unless separately agreed in writing.

## Supported scope

Public repositories and explicitly identified public deployments are in scope. Private owner infrastructure, third-party services, social engineering, denial-of-service, credential stuffing, financial manipulation and testing against systems without authorization are out of scope.

Researchers must stop when they encounter sensitive data or evidence of access beyond the intended test account and report it privately.
